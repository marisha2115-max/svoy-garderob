# Публикация на GitHub Pages — инструкция, ещё не выполнена

Подготовлена статическая версия; сервер Node для работы на Pages не нужен. Поддерживаются корень домена и адрес вида `https://USERNAME.github.io/REPOSITORY/`. В репозитории на GitHub Free для Pages используйте публичный репозиторий.

## До подтверждения

1. Выполнить тесты, typecheck, чистую сборку и browser/pages.mjs. Проверить output/pages/network-report.json: только origin локального статического сервера, без внешних запросов. Проверка охватывает / и /репозиторий/,390×844/768×1024, загрузку фото, реальный Worker, правила, ручную сборку, сохранение/reload и ZIP export/import.
2. Проверить output/pages/files.json: каждый файл строго меньше100000000 байт, сумма меньше1000000000 байт. В сборке нет нейромоделей и wasm из-за лицензионного решения; версия обработчика задаётся хешем имени Worker. Исходники и лицензии зависимостей — в LICENSES.
3. Запустить scripts/prepare-pages-repository.mjs. Он создаёт output/pages/repository (чистые исходники с подтверждёнными38 фото), output/pages/repository.zip и output/pages/site.zip (только сайт), проверяет секреты/приватные пути и пишет отчёт без значений секретов.
4. Проверить состав archive и итоговый отчёт. Архивы не отправлены и сайт не опубликован. Дождаться явного подтверждения владельца на push и публикацию.

Не отправлять существующую историю рабочего репозитория: в ней есть исторические модели и частные рабочие документы. Очищенный snapshot намеренно не содержит .git. После подтверждения создаётся новая история или отдельный чистый репозиторий. Переписывание/удаление старой истории автоматически не производится.

## После явного подтверждения: вариант без Actions, ветка gh-pages

1. Создать пустой публичный репозиторий на GitHub. Домен покупать не нужно. Через браузер можно войти в свой аккаунт; ключи приложению не требуются.
2. Для исходников использовать только output/pages/repository. Инициализировать новую Git-историю и добавить удалённый репозиторий. Отправить исходники в main — только после подтверждения push.
3. Распаковать output/pages/site.zip в отдельную папку. index.html, .nojekyll, assets, shared-wardrobe и LICENSES.txt должны находиться в корне папки, а не ещё на один уровень глубже.
4. Создать отдельную ветку gh-pages с содержимым именно статического каталога. Не копировать исходники, output, .env, node_modules или архивы в эту ветку. Отправить ветку — только после подтверждения публикации.
5. GitHub → Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: gh-pages → Folder: /(root) → Save.
6. Дождаться завершения Pages и открыть выданный HTTPS-адрес. Дополнительных API-ключей нет. .nojekyll предотвращает ненужную обработку Jekyll.

Автоматического workflow публикации на push нет. Для будущих обновлений повторить локальную сборку и проверки, затем обновлять gh-pages после разрешения. Хеши main/CSS/Worker меняются вместе с содержимым; HTML ссылается на актуальные имена. Если Safari держит старую открытую вкладку, закрыть её и открыть постоянный адрес заново.

## Проверка после размещения

На новом устройстве: все38 фото декодируются; общий набор не заменяет личные вещи; подбор и ручной образ сохраняются; ZIP скачивается и импортируется. На iPhone: добавить постоянный HTTPS-адрес на экран «Домой», открыть с иконки, сохранить образ, полностью закрыть и открыть снова, проверить фото/образ и ZIP. Эта физическая проверка не выполнена автоматическими инструментами.

Личные данные привязаны к origin браузера. Новый домен, другой браузер, Safari и отдельное установленное веб-приложение могут иметь отдельное хранилище; для гарантированного переноса использовать ZIP. Сервис-воркер и офлайн-запуск не реализованы.

Официальные инструкции: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site ; https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits .
