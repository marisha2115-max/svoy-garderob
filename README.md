# Свой гардероб

[Открыть опубликованное приложение](https://marisha2115-max.github.io/svoy-garderob/) — GitHub Pages, HTTPS.

Демонстрационное веб-приложение для хакатона: гардероб, подбор по погоде и описаниям вещей, ручная сборка коллажа, сохранение образов и ZIP-копии. Подбор выполняется по правилам. Внешнего AI-стилиста и анализа сочетаемости изображений нет.

## Запуск

Нужны Node.js24 и pnpm11.25.0 (либо совместимый pnpm с lockfile9).

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck
node scripts/build.mjs --out-dir=output/pages/dist
node scripts/serve-static.mjs output/pages/dist /repository/ 8790
```

Откройте `http://localhost:8790/repository/`. Для корня передайте `/` вместо `/repository/`. Сборка содержит относительные пути, хешированные JS/CSS/Worker и CSP в HTML. Sourcemap не публикуются. Сборка требует подтверждённый manifest и файлы из release-assets: отсутствие набора — ошибка, а не пустой гардероб.

Готовый каталог не смешивается со старой сборкой. Для следующей проверки выберите новый пустой каталог через `--out-dir=output/pages/dist-next`. Не копируйте поверх него старые модели/wasm или архивы импорта.

## Общий набор

Владелец подтвердил38 фотографий для публичного показа. Файлы и SHA256 перечислены в release-assets/photo-approval.json. На новом устройстве набор появляется один раз; он не заменяет непустой личный гардероб и не возвращает удалённые вещи при каждом входе. Это общий исходный набор, а не синхронизация изменений. Право свободного перераспространения фотографий пользователями не предоставляется.

Код поддерживает сокращённый набор0..38 вещей. При исключении фотографий нужно одновременно обновить manifest и approval; сборка копирует только подтверждённые записи. Публичные фотографии отделены от личных файлов.

## Обработка фото

Публичная версия может убрать однородный фон простым алгоритмом на устройстве. На сложном фоне или при недостаточном контрасте оставляет оригинал. Категорию и название укажите вручную. Вырезка применяется только после просмотра и явного выбора. Обрезка доступна отдельно.

SegFormer и ORMBG исключены из публичной версии по лицензионным причинам/неопределённости; модели, обучающие данные, ONNX Runtime и wasm не публикуются и не загружаются. См. LICENSES и docs/model-license-audit.md. Во время работы приложение не отправляет фотографии на внешние сервисы.

## ZIP-копия и перенос

Меню → «Копия и перенос» → «Скачать копию». Сохраните ZIP на устройство. В нём оригиналы, обрезки, вырезки, выбор фото, описания и сохранённые образы; лимит250МБ. Для восстановления выберите «Восстановить из файла» → «Добавить копию». Импорт добавляет отдельные записи, сохраняя существующие; повторный импорт создаёт ещё одну копию.

При переходе с локального адреса на опубликованный сайт личные данные автоматически не переносятся: экспортируйте ZIP на старом адресе и импортируйте на новом.

## Ограничения

- Хранение только в IndexedDB этого браузера. Аккаунтов, облачной синхронизации и гарантированной защиты от очистки браузера нет. Делайте ZIP-копии.
- Запуск без сети не обеспечен: service worker не реализован.
- На iPhone: открыть постоянный HTTPS-адрес в Safari → «Поделиться» → «На экран “Домой”»; включить «Открывать как веб-приложение», если переключатель доступен. Добавление значка не является гарантией офлайн-работы или переноса данных из Safari.
- Проверки Chromium с мобильной шириной не заменяют настоящий Safari/iPhone. Физический iPhone отдельно не проверен.

## Проверка и публикация

`pnpm test`, `pnpm typecheck`, `pnpm verify:pages`. Для браузерной проверки установите Chromium/Edge и при необходимости задайте BROWSER_PATH. По умолчанию используется Edge из стандартного пути Windows.

Подробности: docs/github-pages.md. Скрипт `pnpm prepare:pages` создаёт чистый snapshot репозитория без старой истории, личных файлов, ключей и моделей. Не отправляйте старую рабочую папку/историю вместо него. Публикация и push выполняются только после отдельного подтверждения владельца.
